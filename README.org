* What is Kaizen?

Kaizen is an opinionated, keyboard-driven developer environment manager for
macOS and Linux. It installs native packages, runtime tools, and dotfiles from
one feature configuration.

Its components are deliberately small:

- Python 3.11+ orchestrates the workflow;
- Homebrew, dnf, or apt installs system packages;
- mise installs runtimes and global development tools;
- chezmoi renders and applies dotfiles.

* Install

Requires Git and curl. The installer reuses Python 3.11+ when available or
installs an isolated Python 3.12 runtime through standalone uv.

Before =kaizen sync=, install [[https://www.chezmoi.io/install/][chezmoi]]. On Linux, also install
[[https://mise.jdx.dev/getting-started.html][mise]] before installing runtime tools. Missing prerequisites stop the
workflow rather than silently skipping dependencies.

#+BEGIN_SRC shell
curl -fsSL https://raw.githubusercontent.com/artawower/kaizen/master/install.sh | sh
#+END_SRC

The remote script clones Kaizen to =~/.local/share/kaizen=, creates
=~/.config/kaizen/config.toml=, configures chezmoi, and installs a
=~/.local/bin/kaizen= wrapper pinned to the selected Python interpreter. Native
package managers are checked only by commands that use them. On macOS, Kaizen
offers to run the official Homebrew installer when required.

On a first install, the script opens the generated config in your editor
(=$VISUAL=, =$EDITOR=, or =vi=) so you can replace the placeholder identity
and adjust preferences. Review the feature catalog before syncing; all
non-archived recipes for this OS will participate. After you save and quit, the installer offers to run
=kaizen sync= immediately. A config still containing placeholder values falls
back to manual instructions, as do sessions without a controlling TTY. If you
decline the prompt or skip editing, run later:

#+BEGIN_SRC shell
kaizen sync
#+END_SRC

If =~/.local/bin= is not yet on =PATH=, the installer prints the equivalent
command with its full path.

* Repository layout

#+BEGIN_SRC text
features/editor.toml
features/languages.toml
features/tiling.toml
features/desktop.toml
features/development.toml
features/system.toml
features/tools.toml
features/hooks/<name>/post_install.py

dotfiles/             # chezmoi source
dotfiles/.chezmoidata.toml
config.example.toml
kaizen.py
#+END_SRC

Each =features/*.toml= file groups named feature sections. Packages and mise
versions live together in each section; only real hooks and their assets need
separate files. Category files have no inheritance or shared defaults. Every
feature is active on its supported OS unless its section declares
=archive = true=. There is no user-maintained feature enable list.

* Configuration source of truth

=config.example.toml= is the authoritative source for explicit user intent,
preferences, and requirements that agents must preserve when adapting or
replacing applications. Agents must read it in full before adding, changing,
or adapting application configurations, and update intended behavior there
first. It includes shortcut intents, workspace names, and terminal preferences;
it is not an inventory of installed software or every native setting.

Software, versions, platforms, and installation hooks belong in
=features/*.toml=. Native application configs implement the intended behavior.

** Shortcut intents

The top-level =shortcuts= list is copied into
=~/.config/kaizen/config.toml= by the installer for new installations. Each
entry has an English =description= and =keys=: a list of alternative QWERTY
key sequences. Uppercase letters denote shifted letters; =1..9= denotes an
indexed action family.

AI agents use these intents when adapting any application with matching
capabilities, including editors, file managers, and pane managers. Super,
leaders, modes, and activation mechanisms are application-specific; they are
not part of the sequences. Agents must report unsupported actions or conflicts
rather than silently changing their meaning.

This catalog is for AI adaptation, not runtime binding generation. Application
configs contain direct QWERTY bindings; chezmoi does not resolve or remap them.
Existing installations can copy the =shortcuts= list from the example into
their local Kaizen config.

** Terminal

=[terminal].shell= selects the preferred interactive shell. The =completion=
entry declares a provider, whether it is required, and an upstream =source=
reference for adaptation. Carapace is required for every managed interactive
shell, including newly added or restored shells; this requirement is independent
of the preferred shell. The source URL is documentation, not an installation
recipe. Terminal emulators such as Ghostty remain features, not global
requirements.

* Usage

#+BEGIN_SRC shell
kaizen              # show command help and documentation
kaizen docs         # show documentation and local paths
kaizen install      # install packages and tools without applying dotfiles
kaizen sync         # install dependencies and apply dotfiles
kaizen update       # upgrade native packages, mise tools, and feature integrations
kaizen self-update  # fast-forward a managed installation from its remote branch
kaizen bump         # developer: update tools entries in feature catalogs
kaizen capture      # developer: re-add known mutable dotfiles to the source
kaizen status       # show installation mode, source, features, and tools
#+END_SRC

Running ~kaizen~ without arguments is safe: it prints help instead of changing the
system. The same output is available through ~kaizen help~ and ~kaizen --help~.
Interactive help, documentation, status, warnings, and errors use restrained ANSI
colors. Colors are disabled for pipes, redirects, =TERM=dumb=, and =NO_COLOR=.

~kaizen self-update~ updates only remote installations created by the installer.
It refuses development checkouts, detached branches, and installations with
local changes. Run ~kaizen sync~ separately after an update.

~kaizen install~ performs these steps:

1. Discover non-archived features for the current OS and validate user dependencies.
2. Install feature and user packages with the native package manager.
3. Merge feature and user tools into the generated mise config and install them.
4. Install missing feature integrations without refreshing existing ones.

It does not generate the chezmoi data overlay or apply dotfiles. ~kaizen sync~
validates the same inputs, generates the overlay, runs the dependency workflow,
and then runs =chezmoi apply= without =--force=, preserving its normal
confirmation when destination files were changed locally. =just apply= also
keeps this protection.

~kaizen update~ upgrades native packages and mise tools, then refreshes applicable
feature integrations. Helix Steel fetches and rebuilds only when its source
revision changes; Forge packages are reinstalled only when their remote revision
changes.

* Configuration

Committed defaults live in =dotfiles/.chezmoidata.toml=. Machine-local
overrides live in =~/.config/kaizen/config.toml=:

#+BEGIN_SRC toml
layout = "colemak"

[ui]
font_size = 16

[models]
default = "anthropic/claude-sonnet-4-6"
#+END_SRC

Chezmoi recursively merges settings dictionaries. Scalars and lists replace their
default values. =config.example.toml= remains authoritative for agent-facing
configuration intent; the local config supplies machine-specific runtime
overrides. Its recommendations are adapted directly into native application
configs rather than interpreted as a runtime generator.
The =layout= setting configures OS keyboard layout where supported; it no longer
selects application keymaps.

Additional machine-local packages and mise tools can be declared in
=~/.config/kaizen/dependencies.toml=:

#+BEGIN_SRC toml
[tools]
node = "22"
"npm:typescript" = "latest"

[macos]
brew = ["jq", "shellcheck"]
cask = ["zed"]

[macos.brew_args]
jq = ["--HEAD"]

[linux]
dnf = ["jq", "ShellCheck"]
apt = ["jq", "shellcheck"]
flatpak = ["dev.zed.Zed"]
#+END_SRC

The file is optional. Kaizen validates it before making changes, installs its
native packages after applicable feature packages, and gives its =[tools]= entries
precedence over feature mise versions. Kaizen does not modify this user-owned
file during =bump=.

Before applying dotfiles, Kaizen writes the ignored
=dotfiles/.chezmoidata/99-user.toml= snapshot with normalized user settings.
Direct chezmoi commands read the last snapshot, not live user edits. Refresh
it through =kaizen sync= after changing user configuration.

Dependency lock files and generated package caches are not versioned. Versions
that should stay explicit belong in each feature's inline =tools= table. External
skills retain their exact upstream contents.

* Catalog and OS filtering

Kaizen reads named sections from =features/*.toml=. For example:

#+BEGIN_SRC toml
[helix]
brew = ["git", "marksman", "helix"]
dnf = ["git", "marksman", "helix", "nvim"]
apt = ["git", "marksman", "hx"]

[helix-steel]
archive = true
tools = { rust = "latest", "cargo:schemat" = "latest" }
post_install = "features/hooks/helix-steel/post_install.py"
#+END_SRC

This shortened example shows an archived alternative; see =features/editor.toml=
for the actual catalog. Native manager keys are flat, and =tools= contains mise
versions. =platforms= defaults to macOS and Linux; =platforms = ["macos"]= or
=["linux"]= restricts the whole recipe. Optional =distributions= narrows Linux
eligibility to IDs such as =fedora= and =fedora-asahi-remix=. Discovery is ordered
by catalog filename, then feature name; user tool versions take precedence.
The filter covers packages, mise tools, and hooks. Dotfiles are managed separately: chezmoi applies files present in
its source tree, with general platform and generated-file exclusions. A Linux
machine can therefore receive an unused Mango config even when its distro is
not eligible for installing Mango.

For example, =[rift]= in =features/tiling.toml= applies only to macOS; =niri= applies to
Linux, and the MangoWM hook is restricted to its supported Fedora systems.
Multiple applicable WM packages can coexist. Kaizen does not pick a running
WM or enable its service.

The active skhd profile lives in =~/.config/yabai/skhdrc=. The normal
=~/.config/skhd/skhdrc= selects it using skhd's native include:

#+BEGIN_SRC text
.load "../yabai/skhdrc"
#+END_SRC

The Komorebi profile is archived under =.arhive/komorebi/=. Restore it before
selecting =.load "../komorebi/skhdrc"=; restoring does not activate it.
Use skhd's normal service and reload configuration with =skhd --reload= when
needed; no custom LaunchAgent or feature selector is required. Keep only
one WM profile loaded to avoid conflicting hotkeys.

The =wayland= section supplies shared Wayland desktop utilities.
=helix= installs official Helix and =helix-steel= builds the
fork. Both can be installed; the selected executable still depends on PATH.

For existing configs, remove =[features]=, =[tiling].variant=, and
=[helix].variant=. Kaizen rejects old selectors instead of silently ignoring
previously disabled entries. This model installs all non-archived applicable
features, including recipes that used to be disabled; review the catalog and
archive unwanted entries before syncing.

* Archive development experiments

Project skills =archive= and =unarchive= move experiments to and from
=.arhive/<name>/=, preserving repository-relative paths and adjusting their
dependencies and integrations. The named section stays in its category catalog
with =archive = true=; packages, tools, and hook paths remain declared but
inactive. An optional =dotfiles= list in that section contains
repository-relative source paths and helps discovery; the agent also searches
for related files. Installed tools and live configs are left unchanged.

=archive = true= excludes packages, mise tools, and feature hooks. It does not
hide dotfiles: move owned files out of the chezmoi source to stop managing them.
Keep shared selectors active and resolve references before archiving a selected
profile. Unarchive restores files without selecting that profile; conflicting
destinations require an explicit decision, not a silent overwrite.

Existing global package and mise upgrades can still affect previously installed
tools; archive status is not an uninstall or version freeze.

In Pi, run =/reload=, then =/skill:archive yabai= or =/skill:unarchive yabai=.
