* What is Kaizen?

Kaizen is an opinionated, keyboard-driven developer environment manager for
macOS and Linux. It installs native packages, runtime tools, and dotfiles from
one feature configuration.

Its components are deliberately small:

- Python 3.11+ orchestrates the workflow;
- Homebrew, dnf, or apt installs system packages;
- mise installs runtimes and global development tools;
- chezmoi renders and applies dotfiles.

* Install

Requires Python 3.11+, Git, and Homebrew, dnf, or apt.

#+BEGIN_SRC shell
curl -fsSL https://raw.githubusercontent.com/artawower/kaizen/master/install.sh | sh
#+END_SRC

The remote script clones Kaizen to =~/.local/share/kaizen=, creates
=~/.config/kaizen/config.toml=, configures chezmoi, and installs a
=~/.local/bin/kaizen= wrapper.

Edit the generated config, then run:

#+BEGIN_SRC shell
kaizen sync
#+END_SRC

If =~/.local/bin= is not yet on =PATH=, the installer prints the equivalent
command with its full path.

* Repository layout

#+BEGIN_SRC text
features/<name>/
  packages.toml
  mise.toml
  post_install.py
  variants/<name>/
    packages.toml
    mise.toml
    post_install.py

dotfiles/             # chezmoi source
dotfiles/.chezmoidata.toml
config.example.toml
kaizen.py
#+END_SRC

Only =packages.toml= is required. The remaining feature and variant files are
optional.

* Usage

#+BEGIN_SRC shell
kaizen sync         # install enabled features, mise tools, and dotfiles
kaizen update       # upgrade native packages and mise tools
kaizen self-update  # fast-forward a managed installation from its remote branch
kaizen bump         # developer: update mise pins in feature-local manifests
kaizen capture      # developer: re-add known mutable dotfiles to the source
kaizen status       # show installation mode, source, features, and tools
#+END_SRC

~kaizen self-update~ updates only remote installations created by the installer.
It refuses development checkouts, detached branches, and installations with
local changes. Run ~kaizen sync~ separately after an update.

~kaizen sync~ performs these steps:

1. Validate enabled features and selected variants.
2. Install packages with the native platform package manager.
3. Merge enabled feature and variant =mise.toml= files.
4. Run =mise install=.
5. Generate the machine-local chezmoi data overlay.
6. Run =chezmoi apply=.

* Configuration

Committed defaults live in =dotfiles/.chezmoidata.toml=. Machine-local
overrides live in =~/.config/kaizen/config.toml=:

#+BEGIN_SRC toml
layout = "colemak"

[ui]
font_size = 16

[features]
core = true
frontend = true
tiling = true

[tiling]
variant = "yabai"

[kaizen.shortcuts]
"nav.down" = ["n"]
"nav.up" = ["e"]

[models]
default = "anthropic/claude-sonnet-4-6"
#+END_SRC

Kaizen recursively merges dictionaries. Scalars and lists replace their
default values, so every setting, model, and shortcut can be overridden.

Before applying dotfiles, Kaizen links the user config as the ignored
=dotfiles/.chezmoidata/99-user.toml=. Chezmoi reads this overlay automatically,
so direct =chezmoi diff= and =chezmoi apply= commands always use current values.

* Variants

A feature with variants reads its base manifest and the selected variant:

#+BEGIN_SRC text
features/tiling/packages.toml
features/tiling/variants/yabai/packages.toml
#+END_SRC

Select it in the user config:

#+BEGIN_SRC toml
[features]
tiling = true

[tiling]
variant = "yabai"
#+END_SRC

Available tiling variants are =aerospace=, =glazewm=, =komorebi=, and =yabai=.
Changing a variant does not uninstall packages from the previously selected
variant.
