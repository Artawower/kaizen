#+TITLE: Kaizen feature format

* Category catalogs

#+BEGIN_SRC text
features/editor.toml
features/languages.toml
features/tiling.toml
features/desktop.toml
features/development.toml
features/system.toml
features/tools.toml
features/hooks/<name>/post_install.py
#+END_SRC

Every top-level table in a category catalog is an independent feature. Names
are unique across all catalogs. Kaizen discovers =features/*.toml= in filename
order, then feature-name order. Categories provide no inheritance or defaults;
there is no user =[features]= enable list and no variant selection.

* Feature section

#+BEGIN_SRC toml
[example]
description = "Example CLI tools"
brew = ["jq"]
dnf = ["jq"]
apt = ["jq"]
brew_args = { jq = ["--HEAD"] }
tools = { go = "latest" }
dotfiles = ["dotfiles/dot_config/example"]
#+END_SRC

Native manager keys are flat: =taps=, =brew=, =cask=, =dnf=, =apt=, and =flatpak=.
Use real package names for their manager. Optional =brew_args= maps package
names to flag lists. =tools= is an inline table of mise tool names and versions;
there are no separate package or mise manifests for individual features.

Kaizen merges applicable =tools= in discovery order into =~/.config/mise.toml=.
User =[tools]= in =~/.config/kaizen/dependencies.toml= overrides feature versions.
Developer =bump= captures live versions into applicable feature sections while
preserving other sections and user-owned tool overrides.

* OS eligibility

Omitted =platforms= means both macOS and Linux. Restrict a whole recipe with
=platforms = ["macos"]= or =platforms = ["linux"]=. Package manager keys select
native commands, not whole-feature eligibility; explicitly restrict hooks and
tools when they are platform-specific.

For a distro-specific integration:

#+BEGIN_SRC toml
[mangowm]
platforms = ["linux"]
distributions = ["fedora", "fedora-asahi-remix"]
post_install = "features/hooks/mangowm/post_install.py"
#+END_SRC

=distributions= applies only on Linux and matches =/etc/os-release= IDs.
The eligibility filter covers packages, mise tools, and hooks. Dotfiles are
independent: chezmoi uses general platform and generated-file exclusions, not
per-feature gates. An unused app config may still be deployed on its platform.
Installation does not select a running WM or activate its service.

* Archive status

Set =archive = true= inside the feature section to exclude its whole recipe;
omission means active. Keep the section, dependencies, metadata, and hook path
in the catalog. Move owned dotfiles, hooks, and assets to =.arhive/<name>/=,
preserving repository-relative paths. Remove the flag after restoring them;
there is no need to write =archive = false=.

The flag alone does not hide dotfiles or remove deployed files. Archive does
not uninstall packages, stop services, or prevent global package/mise upgrades.

* Skills inventory

A feature may declare global agent skills in =owner/repo@skill= format:

#+BEGIN_SRC toml
[ai]
skills = ["dietrichgebert/ponytail@ponytail"]
#+END_SRC

The AI feature supplies the =skills= CLI through mise. Kaizen combines skills
from active, applicable features and installs them after mise, before hooks.
Repeated declarations are deduplicated; different sources for the same skill
name are rejected. =install= and =sync= skip skills already installed from the
requested source. =update= refreshes only declared skills through =skills add=;
unlisted skills are neither updated nor removed. If the CLI is unavailable,
Kaizen reports a skip. Fresh mise installations use =mise exec= when =skills=
is not yet on =PATH=. Installation and CLI-output errors stop the operation.

* Dotfiles metadata

Optional =dotfiles= lists repository-relative source paths. It guides AI
ownership discovery, not runtime assembly or deployment. Shared files stay
active when another feature needs them. Resolve selectors such as skhd =.load=
before moving a selected profile; restoring files does not switch selection.

* Integrations

Declare an optional repository-relative =post_install= path in the feature
section. Only actual hooks and their assets need directories under
=features/hooks/=. Archived or unsupported features do not require their hook
to be present; applicable features must reference an existing file.

Hooks run with Kaizen's Python interpreter and receive the OS and action:

#+BEGIN_SRC text
post_install.py macos sync
post_install.py fedora update
post_install.py ubuntu sync
#+END_SRC

The OS is =macos= or the Linux distribution ID. Both =install= and =sync= pass
=sync=. Integrations should be idempotent and refresh existing installations
explicitly on =update=. Keep privileged changes opt-in. Validate catalog edits
and templates without applying them to the real home.
