#+TITLE: Kaizen feature format

* Structure

#+BEGIN_SRC text
features/<name>/
  packages.toml
  mise.toml
  post_install.py
  variants/<variant>/
    packages.toml
    mise.toml
    post_install.py
#+END_SRC

Only the base =packages.toml= is required. Enable the feature with
=[features].<name> = true= and select a variant through
=[<name>].variant= in =~/.config/kaizen/config.toml=.

* Native packages

#+BEGIN_SRC toml
description = "Example tools"
category = "dev"

[macos]
taps = []
brew = ["jq"]
cask = []

[macos.brew_args]
jq = ["--HEAD"]

[linux]
dnf = ["jq"]
apt = ["jq"]
flatpak = []
#+END_SRC

Use package names that exist for the corresponding manager. Variants add to
the base packages; changing variants does not uninstall earlier packages.

* Runtime tools

Declare tools in =mise.toml=, not in =packages.toml=:

#+BEGIN_SRC toml
[tools]
python = "latest"
"npm:typescript" = "6.0.3"
#+END_SRC

Kaizen merges these declarations into =~/.config/mise.toml=. The file is a
generated output. Variant versions override the base feature, and user
=[tools]= in =~/.config/kaizen/dependencies.toml= overrides feature versions.

* Integrations

A =post_install.py= hook runs with the same Python interpreter as Kaizen.
Its arguments are the OS identifier and action:

#+BEGIN_SRC text
post_install.py macos sync
post_install.py fedora update
post_install.py ubuntu sync
#+END_SRC

The OS identifier is =macos= or the Linux distribution's =/etc/os-release=
=ID=, such as =fedora=, =fedora-asahi-remix=, =ubuntu=, or =debian=.
Both =install= and =sync= pass the =sync= action. Hooks should avoid refreshing
existing integrations on =sync= and perform explicit refreshes on =update=.

Keep privileged system configuration opt-in. Put dotfile selection rules in
=dotfiles/.chezmoiignore.tmpl=; a package feature flag alone does not define
file ownership. Test package declarations, hooks, and rendered templates
without modifying the real home directory.
