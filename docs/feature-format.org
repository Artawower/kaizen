#+TITLE: Kaizen feature format

* Category catalogs

#+BEGIN_SRC text
features/editor.toml
features/languages.toml
features/tiling.toml
features/desktop.toml
features/development.toml
features/system.toml
features/tools.toml
features/hooks/<name>/post_install.py
#+END_SRC

Every top-level table in a category catalog is an independent feature. Names
are unique across all catalogs. Kaizen discovers =features/*.toml= in filename
order, then feature-name order. Categories provide no inheritance or defaults;
there is no user =[features]= enable list and no variant selection.
Repeat =--feature NAME= on =install=, =sync=, =update=, =status=, or =bump= to select
recipes explicitly. The selection applies for one command only. Omission selects
all applicable non-archived recipes. Unknown, archived, and unsupported names fail
before application; repeated names are deduplicated. There are no presets or tags.

* Feature section

#+BEGIN_SRC toml
[example]
description = "Example CLI tools"
packages = ["jq", "fd"]
package_names = {fd = {dnf = "fd-find", apt = "fd-find"}}
brew_args = { jq = ["--HEAD"] }
tools = { go = "latest" }
dotfiles = ["dotfiles/dot_config/example"]
#+END_SRC

=packages= lists shared native dependencies. Native manager keys remain flat:
=taps=, =brew=, =cask=, =dnf=, =apt=, and =flatpak=. They add manager-specific
packages rather than replacing the shared list. Optional =brew_args= maps native
Homebrew names to flag lists. =tools= is an inline table of mise tool names and
versions; there are no separate package or mise manifests for individual features.

=package_names= maps a dependency name to =brew=, =dnf=, and/or =apt= exceptions.
An omitted manager uses the dependency name unchanged. In the example, =fd=
installs as =fd= through Homebrew and =fd-find= through dnf or apt. Declare an
exception once; it applies to shared dependencies in every active, eligible
feature. Canonical names and explicitly declared aliases, such as =fd-find=,
identify the same dependency in =packages=. Archived and unsupported features
contribute neither packages nor name exceptions.

Use =packages= only when the dependency should exist on every platform supported
by its feature. Keep platform-specific software in manager lists, and use real
native names there: =dnf = ["fd-find"]= is valid, while =dnf = ["fd"]= is rejected
when the known mapping requires =fd-find=. Packages with different names need an
explicit =package_names= declaration; Kaizen does not guess aliases or query
repositories to verify package availability.

Before installing, Kaizen combines feature packages and user native dependencies
into one ordered plan. Repeated native packages, taps, casks, and Flatpaks are
installed once per manager. Conflicting name exceptions, ambiguous aliases shared
by different dependencies, and differing =brew_args= for the same formula stop
installation before native commands run. Errors identify the declarations
involved. Default flags are an empty list, so a default installation and a
=--HEAD= installation conflict rather than silently choosing one. Flags must
match in order as well as value. These checks cover declarations, not arbitrary
runtime conflicts between unrelated system packages.

Kaizen merges applicable =tools= in discovery order into =~/.config/mise.toml=.
User =[tools]= in =~/.config/kaizen/dependencies.toml= overrides feature versions.
Developer =bump= captures live versions into applicable feature sections while
preserving other sections and user-owned tool overrides.

* Mise execution

Kaizen generates =~/.config/kaizen/bootstrap.toml= and executes =mise bootstrap=
in isolation from unrelated global, system, and project mise configs. Linux
packages become manager-qualified =[bootstrap.packages]= entries. Exactly one
native Linux manager is chosen; Flatpak stays system-wide and requires the
executable and a configured Flathub remote. Real Homebrew commands run in a
pre-packages hook, preserving taps, casks, and custom formula flags.

An optional =bootstrap= table passes native mise bootstrap declarations through:

#+BEGIN_SRC toml
[example.bootstrap.macos.defaults."com.apple.dock"]
autohide = true
tilesize = 32
#+END_SRC

Different keys merge; conflicting values fail before execution. =packages= and
=hooks= inside this table are reserved for Kaizen's generated installation plan.
Mise validates and executes the remaining native sections. Use absolute or
home-relative resource paths where the native section supports them; the
configuration is generated outside the catalog directory.

Tools install before one sequential bootstrap task installs skills, runs feature
hooks, and, for =sync= only, applies chezmoi. =update= uses =--update --upgrade=
and refreshes integrations without applying dotfiles. Updates target declared
packages and tools rather than requesting manager-wide upgrades, though native
package dependencies may also change. =--dry-run= previews using a temporary
config without replacing generated configs or the chezmoi overlay. Mise prints
tasks without running them; file-template =exec()= can still run during preview.

* OS eligibility

Omitted =platforms= means both macOS and Linux. Restrict a whole recipe with
=platforms = ["macos"]= or =platforms = ["linux"]=. Package manager keys select
native commands, not whole-feature eligibility; explicitly restrict hooks and
tools when they are platform-specific.

For a distro-specific integration:

#+BEGIN_SRC toml
[mangowm]
platforms = ["linux"]
distributions = ["fedora", "fedora-asahi-remix"]
post_install = "features/hooks/mangowm/post_install.py"
#+END_SRC

=distributions= applies only on Linux and matches =/etc/os-release= IDs.
The eligibility filter covers packages, mise tools, bootstrap declarations,
skills, and hooks. With explicit =--feature= selection, dotfiles are limited to
selected declarations and chezmoi's platform/generated-file exclusions. Without
selection, chezmoi retains its full-source behavior.
Installation does not select a running WM or activate its service.

* Archive status

Set =archive = true= inside the feature section to exclude its whole recipe;
omission means active. Keep the section, dependencies, metadata, and hook path
in the catalog. Move owned dotfiles, hooks, and assets to =.arhive/<name>/=,
preserving repository-relative paths. Remove the flag after restoring them;
there is no need to write =archive = false=.

The flag alone does not hide dotfiles or remove deployed files. Archive does
not uninstall packages, stop services, or prevent global package/mise upgrades.

* Skills inventory

A feature may declare global agent skills in =owner/repo@skill= format:

#+BEGIN_SRC toml
[ai]
skills = ["dietrichgebert/ponytail@ponytail"]
#+END_SRC

The AI feature supplies the =skills= CLI through mise. Kaizen combines skills
from active, applicable features and installs them after mise, before hooks.
Repeated declarations are deduplicated; different sources for the same skill
name are rejected. =install= and =sync= skip skills already installed from the
requested source. =update= refreshes only declared skills through =skills add=;
unlisted skills are neither updated nor removed. If the CLI is unavailable,
Kaizen reports a skip. Fresh mise installations use =mise exec= when =skills=
is not yet on =PATH=. Installation and CLI-output errors stop the operation.

* Dotfiles metadata

Optional =dotfiles= lists repository-relative chezmoi source paths inside
=dotfiles/=. With explicit =--feature= selection, only these files or directory
trees are applied. Selective sync validates paths before installing dependencies;
a feature without this list applies no dotfiles. Chezmoi resolves encoded source names and
filters ignored paths. Shared paths are deduplicated. Unlisted files are excluded
from selective sync, and existing destination files are never removed merely
because their feature is no longer selected.

Without =--feature=, =sync= retains full-source application. Resolve selectors
such as skhd =.load= before moving a selected profile; restoring files does not
switch selection.

* Integrations

Declare an optional repository-relative =post_install= path in the feature
section. Only actual hooks and their assets need directories under
=features/hooks/=. Archived or unsupported features do not require their hook
to be present; selected applicable features must reference an existing file.

Hooks run with Kaizen's Python interpreter and receive the OS and action:

#+BEGIN_SRC text
post_install.py macos sync
post_install.py fedora update
post_install.py ubuntu sync
#+END_SRC

The OS is =macos= or the Linux distribution ID. Both =install= and =sync= pass
=sync=. Integrations should be idempotent and refresh existing installations
explicitly on =update=. Keep privileged changes opt-in. Validate catalog edits
and templates without applying them to the real home.
