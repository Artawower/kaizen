#+title: Feature Module Format

Each feature is a single =.nix= file in =dotfiles/dot_config/nix/modules/features/=.
The file is auto-imported by =feature-loader.nix= via =builtins.readDir=.

* Structure

#+begin_src nix
{ config, lib, pkgs, ... }:

let
  cfg      = config.conf.features.helix;
  isDarwin = pkgs.stdenv.isDarwin;
in {
  # ── 1. Declare the enable option ─────────────────────────────────────────
  options.conf.features.helix.enable = lib.mkEnableOption "Helix editor + LSP";

  config = lib.mkMerge [

    # ── 2. Always register metadata (even when disabled) ─────────────────
    {
      conf.featureRegistry.helix = {
        description = "Helix editor + marksman LSP";
        category    = "editor";
      };
    }

    # ── 3. Conditional: packages + brew (only when enabled) ───────────────
    (lib.mkIf cfg.enable {
      conf.packages.nix = with pkgs; [ helix marksman ];

      # macOS deps — declared inline, exported via darwin-deps.json bridge
      conf.packages.darwinCasks = lib.optionals isDarwin [ "some-app" ];
      conf.packages.darwinTaps  = lib.optionals isDarwin [ "owner/tap" ];
    })
  ];
}
#+end_src

* Sections

** =options.conf.features.<name>.enable=
The Nix module option. Controlled at runtime by =data.toml= (written by
=kaizen configure= after the wizard). The option description appears in
=nix-darwin= / =home-manager= documentation output.

** =conf.featureRegistry.<name>=
Always-active metadata block — populated regardless of the =enable= flag so
the full feature list is available in =feature-meta.json= even on a fresh
machine where nothing is enabled yet.

| =description= | Human-readable label shown in =kaizen configure= wizard |
| =category=    | Group key (=editor=, =dev=, =terminal=, =system=, ...)  |
| =update=      | Commands run by =kaizen update= after backend update completes |
| =bump=        | Workflow for =kaizen bump=: =before=, =run=, =capture= fields  |

** =conf.packages.nix=
List of =nixpkgs= attribute paths. Accumulates across all enabled feature
modules and is mapped to =home.packages= by =adapters/home-manager.nix=.

#+begin_src nix
conf.packages.nix = with pkgs; [ go gopls go-tools ];
#+end_src

** macOS deps (darwin JSON-bridge)

Darwin-specific deps are declared **inline** in the feature's =.nix= file
using the options below. The Home Manager activation step writes them to
=~/.config/kaizen/darwin-deps.json=; =darwin.nix= reads that file and merges
the values into =homebrew.*= and =system.activationScripts=.

The old =*.darwin.nix= sibling-file pattern is **deprecated and removed**.

#+begin_src nix
# features/mytool.nix (inline darwin section)
(lib.mkIf cfg.enable {
  conf.packages.darwinCasks        = lib.optionals isDarwin [ "mytool" ];
  conf.packages.darwinTaps         = lib.optionals isDarwin [ "owner/tap" ];
  conf.packages.darwinBrews        = lib.optionals isDarwin [ { name = "formula"; } ];
  conf.packages.darwinBrewFormulas = lib.optionalString isDarwin ''brew "formula"'';
  conf.darwin.activationScripts = lib.optionalAttrs isDarwin {
    setupMytool = ''echo "setting up mytool"'';
  };
}
#+end_src

All keys are optional — omit what you don't need.

* kaizen bump

Features declare their bump workflow in =conf.featureRegistry.<name>.bump=.
=kaizen bump= runs the workflow for every enabled feature — no external manifest
file is needed.

Example from =mise.nix=:

#+begin_src nix
conf.featureRegistry.mise = {
  description = "Mise toolchains";
  category = "dev";
  bump = {
    before  = [{ run = [ "mise" "install" ]; onFailure = "fail"; }];
    run     = [{ run = [ "~/.config/scripts/mise-bump" ]; onFailure = "fail"; }];
    capture = [ "~/.config/mise.lock" ];
  };
};
#+end_src

The =bump= submodule has three fields:

- =before= — hooks that run before the main bump command (e.g. ensure toolchain
  is installed).
- =run= — the main bump commands.
- =capture= — paths passed to =chezmoi re-add= after commands complete.

Each hook has a =run= argv list and an optional =onFailure= policy (default: =warn=).

- =onFailure = "warn"= prints a warning and continues.
- =onFailure = "fail"= prints an error and stops the workflow.

Use =--only <feature>= to run the bump workflow for a single feature only
(e.g. =kaizen bump --only mise= or =kaizen bump --only nix-system=).

Features are executed in category order: =dev → system → other → ai=.
dev/toolchain features run first so tools (e.g. =pi= via mise) are upgraded
before AI extension updates that depend on them.

* Adding a new feature

1. Create =dotfiles/dot_config/nix/modules/features/<name>.nix= following the
   structure above.
2. Declare macOS-specific deps inline using =conf.packages.darwin*= and
   =conf.darwin.activationScripts= (with =lib.optionals pkgs.stdenv.isDarwin=).
   No separate =.darwin.nix= file needed.
3. Add an entry to the seed file:
   =dotfiles/dot_config/kaizen/feature-meta.json=.
4. Run =kaizen sync= — =feature-loader.nix= and =darwin.nix= pick up both
   files automatically.

No changes needed to =manifest.toml=, =options.nix=, =darwin.nix=,
=linux.nix=, or =hosts/*.nix=.

* User extensibility

Two mechanisms let users add packages without forking the dotfiles repo.

** =[extra]= in =config.toml=

Edit =~/.config/kaizen/config.toml= manually after running =kaizen configure=.
On the next =kaizen sync= the section is propagated into =data.toml= which Nix reads:

#+begin_example
config.toml → kaizen sync → data.toml → Nix eval
#+end_example

#+begin_src toml
[extra]
nix_packages  = ["ripgrep", "bat"]        # top-level nixpkgs attribute names
brew_casks    = ["istat-menus"]           # homebrew casks (macOS)
brew_formulas = ["ffmpeg"]               # homebrew formulas (macOS)
brew_taps     = ["homebrew/cask-fonts"]  # homebrew taps (macOS)
#+end_src

- =nix_packages= must be valid top-level =nixpkgs= attribute names
  (e.g. =nodejs_22=, not =nodePackages.prettier=). An unknown name produces
  a clear Nix eval error pointing to the exact attribute.
- The wizard never modifies =[extra]=: the section survives =kaizen configure=
  re-runs.
- Changes take effect on the next =kaizen sync=.

** User feature modules

For users comfortable with Nix. Place files in
=~/.config/kaizen/user-features/=. They are auto-discovered alongside
built-in feature modules.

#+begin_src
~/.config/kaizen/user-features/
  mytools.nix          ← standard home-manager module
#+end_src

=*.nix= files receive the full ={ config, lib, pkgs, ... }= module arguments
and can set any home-manager options. Declare macOS deps inline using
=conf.packages.darwin*= and =conf.darwin.activationScripts=.

** Legacy: user-features/*.darwin.nix (backward compatibility)

This pattern is preserved for backward compatibility only. The primary contract
for new features is inline darwin deps in =*.nix= via =conf.packages.darwin*=
and =conf.darwin.activationScripts=.

For user-features (=~/.config/kaizen/user-features/=), =*.darwin.nix= files are
still scanned by =darwin.nix= and remain functional. New user features should
prefer the inline approach.

* Infrastructure modules

Modules that are not user-visible features (fonts, darkman, battery thresholds)
live in =dotfiles/dot_config/nix/modules/system/= and are imported explicitly
in =darwin.nix= / =linux.nix=. They are never auto-discovered.
